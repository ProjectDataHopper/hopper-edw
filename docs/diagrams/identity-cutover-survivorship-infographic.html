Durable Key Grain
Decoupled Entity Clustering

Identity Map: Freezing the Durable Hash

An identity map resolves duplicate raw keys (hk_raw) across disparate source systems into a unified durable surrogate key (hk_durable).

Object: BvIdentityMap
Table: Physical table (upsert, not truncate)
Hop Transform: IdentityLookup
1

Freeze on First Assignment

When a cluster forms, hk_durable is created from MDM ID or the initial master raw hash. Once created, it is frozen forever.

2

Master Flip Resiliency

If CRM flips the preferred master from O100 to K100, hk_master and rule_version update, but hk_durable never changes. Downstream marts never break!

3

Preferred BK is Payload

The human-readable preferred_bk is carried as payload. It can be corrected in place without driving a spurious new SCD2 version row.

Durable Key Stability Mechanism

Load 1 (Initial Assignment) rule_version = 1
Same-as Link: O100 (Master) ➔ K100 (Dup)
hk_durable(O100) = HASH("O100")
hk_durable(K100) = HASH("O100") (Inherited)

Durable key is minted and snapshotted into map_person table.

Load 2 (Master Flips to K100) rule_version = 2
Same-as Link: K100 (Master) ➔ O100 (Dup)
hk_durable(O100) = HASH("O100") [FROZEN!]
hk_durable(K100) = HASH("O100") [FROZEN!]

Master pointer updates to K100, but the durable key remains immutable!

Unmapped Key Policies (unmappedPolicy)

Policy Action When No Map Interval Found Timeline Impact
self (default) Substitutes hk_durable = hk_raw. Entity passes through with its own raw identity until mapped.
quarantine Suppresses the row from main SCD2 stream and routes to quarantine. Only explicitly resolved business keys enter the Business Vault.
drop Silently discards the unmapped raw satellite row. Strict whitelist: unmapped history is ignored.

FROM sat_person_oracle

ORDER BY person_hk COLLATE "C", x_load_ts;

Field-Level Conflict Arbitration

SurvivorshipMerge: Granular Rules Engine

When multiple satellite streams disagree on a column value, SurvivorshipMerge deterministically resolves the winning value based on explicit column ranks, null policies, and delta operations.

Location: In-stream Transform
Trigger: Any non-empty rank on SCD2 field mapping
Unranked: Falls back to SortedSchemaMerge
Rank Arbitration

Field-by-Field Priority

Rank 1 beats Rank 2. Ranks can disagree across fields! Kafka can win email while Oracle wins city.

Null Policies

inherit vs. apply

inherit: null skips rank & keeps existing value (delta/event stream).
apply: null explicitly clears the field (full snapshot/CRUD).

Delta Semantics

Present Flags & Seed

Present Flag tells "omitted from JSON" from "explicit null". seed fills initial gaps without overwriting existing upsert values.

Prior Value: email = 'oracle@example.com'
Kafka (Rank 1): email = NULL, email_present = 'Y'
Resulting Value: NULL

Present flag explicitly confirms the field was cleared, overriding inherit!
