Act 2: The Core Thesis

The Fallacy of "Best of Breed"

"Best tool for each job gives you the best parts. The engineer still needs the whole picture."

What "Best of Breed" Optimizes For
  • • Deep feature silos in one narrow discipline (profiling, lineage, ERD)
  • • Purchasing one category at a time from different vendors
  • • Specialized analysts who live 100% of their day in one tool
What It Costs The Data Engineer
  • • Fragmented context: Truth is split across 5 tools with different names
  • • Constant context switching: Jumping between windows all day
  • • Drift & sync issues: Models, schemas, and jobs diverge silently
  • • Read-only islands: Observing and fixing live in separate tools

The Law of Separation

Three Different Acts

"Looking, deciding, and loading are three different acts. A deliberate write is not a side effect of looking."

ACT 1: HARVEST
Observation Without Mutation

Harvest scans live sources and records what they look like right now. It builds change history without silently rewriting downstream contracts.

ACT 2: GATES
Policy Enforcement

Schema Drift Gate and Quality Gate evaluate whether this wave may load. If a column changed or quality rules fail, execution stops safely before corruption occurs.

ACT 3: UPDATE & PUBLISH
Deliberate Write

The update executes, loads targets, and publishes updated physical layouts back to the catalog as a conscious, auditable act.

The Editability Imperative

Seeing & Fixing in the Same Place

Observability without editability is just an expensive alarm clock. An engineer must be able to remediate issues at the exact point of discovery.

The Disconnected World
  1. Catalog alerts: "Column length mismatch!"
  2. Open Jira ticket, assign to data engineer
  3. Engineer pulls Git repo for pipeline code
  4. Engineer requests DBA permission for ALTER TABLE DDL
  5. Engineer manually updates 3 pipeline mapping transforms
  6. Re-test and deploy across 3 environments
Elapsed time: 2 days • Risk: Manual error
The Hopper EDW World
  1. Schema Gate flags: "Customer_tier length drifted"
  2. System presents Remediation Proposal Dialog
  3. Review proposed SQL: ALTER TABLE VARCHAR(50)
  4. Click [Apply Remediation]
  5. Model updated, DDL executed, pipelines stay valid
  6. Load wave resumes immediately
Elapsed time: 30 seconds • 100% auditable
